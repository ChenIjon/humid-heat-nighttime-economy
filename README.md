# Heat and Humidity Reshape Urban Economic Activity at Night

Contact: chenchen1107@connect.hku.hk

`Main_model.R` fits generalized additive mixed models for city-date economic activity, with temperature-humidity interactions, city-specific effects, calendar controls and AR(1) correlation. It estimates exposure-weighted marginal effects (EWME) and confidence intervals using a date-block bootstrap. The original study analyses were run on a server. The public demonstration uses fully synthetic data and is separate from the study analyses.

## Research environment and dependencies

The main analyses were conducted using Python (version 3.12.9) and R (version 4.4.1), with the primary statistical models implemented using the mgcv package (version 1.9-3).

For the main R analysis and demonstration, install R, mgcv and dplyr in your own environment before running. The main model uses `mgcv::bam` and requires dplyr functions including `across()`; parallel, splines and stats are bundled with R. The research versions above are the server study environment, not the demonstration test environment. A server dplyr version has not been supplied and is not claimed here. Python is part of the broader research environment but is not needed for these R commands. Timing additionally requires data.table and Matrix.

See [examples/TESTING.md](examples/TESTING.md) for the separate demonstration verification record. The demonstration also writes its actual `sessionInfo()` to an ignored output file.

## Data access and publication restrictions

The real transaction-derived input panel is restricted and is not distributed here. Downloading this repository does not provide the data needed to reproduce the study estimates. Aggregation does not establish permission to release transaction-derived data.

In particular, `analysis_data_model_input.csv` contains the filtered and scaled analysis rows, including transaction-derived outcomes. Treat this file, fitted model objects, bootstrap caches and generated summaries as restricted unless their release has been explicitly authorized. Model objects and intermediate artifacts may retain input-derived information. Do not publish them simply because they are aggregated or generated by this code.

`.gitignore` allows code, Markdown documentation and the single fully synthetic example CSV; it excludes real data directories, output directories, fitted models and bootstrap artifacts at every directory depth. Any additional material requires an explicit publication decision. Ignore rules do not remove files already tracked by Git or from repository history; check tracked files before publishing. No tracked-file removal or history rewriting is performed by the example scripts.

## Public synthetic demonstration

From the repository root, run:

```bash
Rscript examples/run_demo.R
```

The included [examples/main_panel_synthetic.csv](examples/main_panel_synthetic.csv) contains 360 simulated city-date rows: three city labels, 120 dates, and all required fields. Every numerical value is generated from a fixed random seed and illustrative distributions. The generator reads no real or aggregated transaction data, estimates no parameters from such data, and reproduces no study results. City labels serve only to match the code's accepted city names. Simulated spending satisfies `model_amt_per_cnt = model_amt / model_cnt`.

The demonstration calls the same main-model functions for TC, TS and AS, with **4 bootstrap replicates per outcome and 1 CPU worker**. It changes run settings, not the model formula. These settings exercise the workflow; its estimates, confidence intervals and significance flags have no research interpretation. It writes only to `examples/output_demo/`, which is ignored by Git, and overwrites its own same-name outputs without reusing bootstrap caches. It does not read or overwrite `data/main_panel.csv` or `output_main/`.

To regenerate the bundled synthetic CSV:

```bash
Rscript examples/generate_demo_data.R
```

Synthetic generation settings are at the top of `examples/generate_demo_data.R`; demonstration run settings are at the top of `examples/run_demo.R`. The generator overwrites only the same-name synthetic CSV. The main demonstration is small and ran in seconds in the recorded test environment; duration on other machines may differ. A separate synthetic Timing check is available with `Rscript Timing/validate_timing.R`.

## Real analysis input

The default input is `data/main_panel.csv`, resolved relative to `Main_model.R`, regardless of the shell's working directory. If this folder is named `R` in a publication checkout, the same relative layout becomes `R/data/main_panel.csv`. No directory restructuring is needed. Place authorized data there or edit `PANEL_FILE` at the top of the script. A missing real input intentionally stops the research run; use the synthetic demonstration when access is unavailable.

One row represents one city and calendar date, with unique `city,DATE` keys:

| Field | Required content |
| --- | --- |
| `city` | City name matching `MAIN_CITIES` in `Main_model.R`; other names are excluded. |
| `DATE` | ISO date `YYYY-MM-DD`; no missing dates or duplicate city-date keys. |
| `TEMP` | Numeric temperature exposure in °C, using the study's exposure aggregation. |
| `RH` | Numeric relative humidity in %, between 0 and 100. |
| `WS` | Numeric wind speed in m/s. |
| `PRECIP` | Numeric precipitation in mm; nonnegative; retain the study's aggregation convention. |
| `PM25` | Numeric PM2.5 concentration in µg/m³. |
| `calendar_type` | One of the nine calendar labels listed below. |
| `model_cnt` | Transaction count (TC), in original count units. |
| `model_amt` | Total spending (TS), in the original monetary units, before scaling. |
| `model_amt_per_cnt` | Average spending (AS): `model_amt / model_cnt`, in matching monetary units. |

Accepted calendar labels are `Monday`, `Tuesday`, `Wednesday`, `Thursday`, `Friday`, `Saturday`, `Sunday`, `Statutory holiday`, and `Make-up workday`.

All required numeric fields must be finite. Counts should be nonnegative integers; spending outcomes must be strictly positive for the Gamma models. Missing/nonfinite values, invalid calendar labels, out-of-range humidity and negative precipitation are excluded during preparation. After filtering, the date-block bootstrap requires a **balanced panel**: every retained date must have one row for every retained city. Provide adequate variation in each smooth covariate and enough dates for the specified spline bases. Input preparation and permissions are the data holder's responsibility; this repository does not recreate the real panel from raw transactions.

The code scales TC by 1, TS by 100,000 and AS by 10 before fitting. Supply unscaled outcomes; do not apply these factors twice. The exported `analysis_data_model_input.csv` contains the scaled outcomes.

## Research run settings and computation

With authorized inputs and the server study environment available:

```bash
Rscript Main_model.R
```

This runs all three outcomes. Edit paths in the script's top parameter section and run settings in `main_model_defaults()` before execution; command-line options and environment variables do not override these main-model defaults.

| Setting | Default | Meaning |
| --- | --- | --- |
| `PANEL_FILE` | `data/main_panel.csv` | Authorized input, relative to the script. |
| `OUTPUT_DIR` | `output_main` | Result directory, relative to the script. |
| `n_boot` | `1000` | Bootstrap refits **per outcome**. |
| `block_length` | `7` | Circular calendar-date block length in days; same date draws across cities. |
| `seed` | `20260912` | Bootstrap random seed. |
| `n_cores` | `1` | Default serial execution; Unix supports parallel outcome/bootstrap workers. |
| `rho_abs_bound` | `0.95` | Bound for the estimated AR(1) correlation. |
| `fix_sp` | `TRUE` | Keep smoothing parameters fixed in bootstrap refits. |
| `force_refit` | `FALSE` | Reuse successful cached bootstrap fits. |
| `export_bootstrap_curves` | `FALSE` | Optional response-curve export. |
| `curve_grid_n` | `100` | Grid size when curve export is enabled. |

The full default run includes pilot/final fits for three outcomes and up to **3,000 bootstrap refits**, with CPU and memory requirements depending on sample size, the design matrix and worker count. Each worker needs memory for data and model matrices. The default runs on one worker; parallel main-model execution is Unix-only in this implementation. Production hardware specifications and a full-run wall-clock benchmark are not supplied, so no fixed production runtime or RAM figure is claimed. First measure a small authorized run in a separate output directory before selecting resources for a full server run.

Same-name summaries and model files are overwritten. Successful bootstrap caches are reused by default; cache acceptance does not fully validate the input data or all run settings. When changing inputs or settings, use a new `OUTPUT_DIR` or set `force_refit = TRUE` to avoid mixing runs. Inspect bootstrap status and successful replicate counts before interpreting confidence intervals.

## Main outputs

All default research outputs are under `output_main/` and excluded from publication by `.gitignore`:

| Output | Content |
| --- | --- |
| `analysis_data_model_input.csv` | Filtered/scaled model input; potentially restricted transaction-derived data. |
| `outcome_specifications.csv` | Responses, model families and scale factors. |
| `models/TC_T1_AR1_final.rds`, corresponding TS/AS files | Fitted AR(1) models. |
| `bootstrap_bundles/{TC,TS,AS}/bootstrap_*.rds` | Cached bootstrap refits/results. |
| `{TC,TS,AS}_bootstrap_status.csv` | Success/failure and errors for each replicate. |
| `{TC,TS,AS}_bootstrap_ewme_replicates.csv` | Replicate-level EWME estimates. |
| `ewme_bootstrap_CI.csv` | Original-fit EWME estimates and bootstrap confidence intervals. |
| `model_diagnostics.csv`, `model_run_status.csv` | Sample sizes, model diagnostics, formulas and run status. |
| `response_curves.csv` | Optional output when `export_bootstrap_curves = TRUE`. |

The demonstration uses the same output layout under `examples/output_demo/` and additionally writes `report.txt` and `demo_session_info.txt`. The default research entry point does not automatically write these two files.

`Timing/` contains the conditional nighttime timing analysis, adjusted for hourly PM2.5, precipitation and wind speed. See [Timing/README.md](Timing/README.md) for its separate hourly input schema and 00-04 workflow. Its real input panels and generated artifacts are subject to the same release restrictions.
